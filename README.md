# Журнал обращений службы поддержки

«Журнал обращений» помогает службе поддержки приводить описания заявок к единому виду, форматировать данные заявителей и искать обращения по ключевым словам. Приложение написано на C# и WPF. Контракты операций проверяются через Pre- и Post-условия.

Кнопка «О сюжете» в главном окне объясняет роль оператора и связывает обработку обращений в ЛР1 с проверкой правил в ЛР2.

## Основные возможности

### Нормализация описания заявки

* **Приведение регистра** — автоматический перевод всего текста в нижний регистр.
* **Очистка от спецсимволов** — удаление пунктуации, знаков препинания и замена переносов строк и табуляций на пробелы.
* **Форматирование пробелов** — замена двойных (и более) пробелов на одинарные, а также удаление пробелов в начале и конце строки.

### Маскирование данных

* **Российские номера телефонов** — преобразование строки в формат `+7 (XXX) XXX-XX-XX` с проверкой количества цифр.
* **СНИЛС** — форматирование ввода в стандартизированный вид `XXX-XXX-XXX XX`.
* **Банковские карты** — приведение 16-значных номеров к формату `XXXX XXXX XXXX XXXX`.

### Поиск по обращениям

* **Поиск по ключевому слову** — поиск по списку обращений, где каждая строка представляет одну заявку.
* **Регистронезависимость** — поиск осуществляется без учета регистра символов.

### Система контрактов (ProcessResult)

* **Pre-условия** — проверка корректности входных данных до начала обработки (например, на пустоту или длину строки).
* **Post-условия** — валидация результатов выполнения (например, отсутствие символов шаблона в итоговой маске).
* **Статистика для UI** — сбор списков пройденных и проваленных условий с отображением успешности операции (`isSuccess`).

### Работа с файлами

* **Импорт** — загрузка текста из конкретного файла или пакетная загрузка `.txt` файлов из выбранной директории.
* **Экспорт** — сохранение обработанного текста (одной строкой или массивом строк) в указанный файл с автоматическим созданием директории при ее отсутствии.

### Калькулятор wp
Вычисление слабейшего предусловия программы относительно заданного постусловия. Например, можно определить, при каких исходных размерах двух очередей в большей окажется больше 100 заявок.
* Поддержка присваиваний, последовательностей операторов и if/else.
* Лексический и синтаксический анализ с построением AST.
* Символьная подстановка и упрощение выражений.
* Проверка определённости операций (например, деления на ноль).
* Пошаговая трассировка вычислений.
* Вывод результата в символьной и текстовой формах.
* Формирование триады Хоара {Pre} S {Post}.
* Три готовых сценария охватывают сравнение очередей VPN и почты, оценку числа заявок на смену по модели времени и два снимка очереди VPN после поступления заявок. Нажмите «Загрузить пример», чтобы заполнить код и постусловие выбранного сценария.

### Проверщик корректности цикла

Окно «Циклы под микроскопом» открывается из раздела «Лабораторная работа №3» левой панели. В нём можно сгенерировать и отредактировать массив, выбрать один из трёх пресетов (`PrefixSum`, `Count > T`, `PrefixMax`), выполнять цикл по шагам или в автоматическом режиме и наблюдать за индексом `j`, накопленным `res` и вариант-функцией `t = n − j`.

Инвариант задаётся словами и формулой; формула разбирается по-русски и вычисляется до и после шага. Блок wp показывает условие `(Inv && B) ⇒ wp(S, Inv)`, его упрощённый вид, пошаговый трейс движка из ЛР-2 и статус сохранения инварианта. Рядом выведены `Pre`, `Inv`, `Post`, `t` и четыре условия тотальной корректности.

## Как запустить

### Через Visual Studio

1. Откройте файл решения (Solution).
2. Убедитесь, что стартовым проектом установлен проект графического интерфейса на базе WPF.
3. Нажмите `Ctrl + F5` (`Ctrl + Fn + F5`) для запуска без отладки.
4. Откроется «Журнал обращений».

## Особенности программы

1. **Архитектура MVVM** — разделение логики и представления с использованием ViewModels (`MainViewModel`, `ContractViewModel`).
2. **Строгая валидация** — генерация исключений (`ArgumentNullException`, `InvalidOperationException`) при нарушении контрактов на уровне ядра нормализации.
3. **Модульное тестирование** — покрытие логики нормализации и фильтрации тестами с использованием фреймворка xUnit (`NormalizationTests`, `TextFilteringTests`).

## Требования

1. .NET 9.0 (для всех проектов решения).
2. Операционная система Windows 10/11 (на остальных системах работа **не гарантируется**).
